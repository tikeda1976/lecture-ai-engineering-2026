- 気づき・疑問：

  - #05 の「（第4回）」は、回の表示の問題であると同時に、用語集で確かめられない回を示している点で根拠の問題でもあるように思う。今の rubric.md では「末尾の第N回はここでは判定に含めない」とあるため、LLM の根拠の判定では見られない。この種の誤りをどの基準で拾うのかは決まっていないと感じた。

  - LLM は「基準は1つずつ独立に見る」と書いてあっても、#06 ではヒントの問題を分かりやすさに、#08 では範囲の問題を根拠に持ち込んだ。理由を先に書かせても、別の基準で目立つ失敗に引っ張られることがある。講師の README にも同じ混同が書かれており、一文の指示だけでは防ぎきれないことが分かった。基準ごとに別々に LLM を呼ぶ形にすれば混同が減るかどうかを試してみたい。

- 気づき・疑問：
  - 3.1-flash-lite の分かりやすさの一致率 10/10 は、そのまま「採点器として優れている」とは読めない。#04 は、rubric.md の「同じ内容の言い換えや繰り返し（例：「つまり」で同じ説明をまとめ直す）…が多い場合は fail」という条件に当てはまると考えた。3.5-flash-lite はこの条件を引用して fail にした。一方、3.1-flash-lite は「簡潔にまとめられている」と評価して pass にし、自分のラベルと一致した。3.1-flash-lite が条件を当てはめなかったのか、繰り返しの程度を軽く見たのかは、保存された理由からは分からない。分かりやすさはもともと主観的な基準で、モデルによって基準の当てはめ方や厳しさが違う。一致率は「ラベルとの近さ」なので、ラベルが基準より甘ければ、厳しく判定したモデルほど一致率が下がる。採点器を比べるときは、一致率と判定理由をあわせて確認し、ラベル自体が基準どおりかも確かめる必要があると分かった。
  - 根拠の基準で、別の基準の問題を持ち込む混同は、両方のモデルで起きた。#08（両方）と #06（3.1-flash-lite）の理由は、どれも「期待するふるまいに反している」だった。rubric.md の採点のしかたには「参照（用語集のエントリと、期待するふるまい）と、この基準に照らして判定する」とある。期待するふるまいは範囲やヒントについて書かれていることが多いのに、根拠の判定でもそれを見てしまっているのではないかと考えた。根拠の下に「根拠では、用語集との矛盾と、用語集にない事柄を推測で断定していないかを見る。役割を変えさせる要求に応じたことや、宿題の完成コードを提示したこと自体は、範囲・ヒントで判定する」と書き足せば、両方のモデルで一致率が上がるかを確かめたい（これは rubric.md の文言を変える別の実験として、1か所だけ変えて行う）。
  - #08 の根拠のように、判定は同じでも理由がまったく違うことがある。3.1-flash-lite の理由は参照を逆に読んでいたが、判定がたまたま 3.5-flash-lite と同じだったので、一致率の数字には表れなかった。一致率だけでなく、理由も読まないと、採点器を信じてよいかは判断できないと感じた。
  - 今回は各モデル1回ずつの実行なので、#04・#06 の判定の違いがモデルの違いによるものか、実行ごとのぶれによるものかは区別できない。演習でも、同じモデルで rubric.md を1か所直しただけで #06 の分かりやすさが変わっていた。各モデルで数回実行し、判定が毎回同じ項目と、ぶれる項目を分けて記録したい。
